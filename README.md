# Здоровье и режим (com.example.healthplan)

Нативное Android-приложение (Kotlin, minSdk 26, targetSdk 34): профиль, расчёт норм, режим питания и примеры блюд, дневник питания с базой USDA, «Мои блюда», распознавание этикеток без интернета, напоминания, которые звонят как будильник.

- **Сборка:** `./gradlew testDebugUnitTest assembleRelease` (JDK 17). Подпись — `~/.android/debug.keystore`.
- **Данные** хранятся только на устройстве (SharedPreferences + JSON, схема версионируется, при обновлении данные не удаляются). Разрешения INTERNET нет. Экспорт/импорт — «Ещё → Данные: экспорт и импорт». Подробно — раздел «Обновления и данные».
- **Формулы и источники** — в [RESEARCH.md](RESEARCH.md).
- **Структура кода:** `core/` (формулы, режим дня), `food/` (база, расчёт граммов, подбор блюд), `ocr/` (Tesseract и парсер этикеток), `alarm/` (будильники), `data/` (хранилище), `ui/`.

## Обновления и данные

**Жёсткое правило: обновление приложения никогда не стирает и не теряет данные пользователя.**

### Где лежат данные (аудит 1.0.1)
| Что | Где | Ключ / поле |
|---|---|---|
| Профиль и цель | SharedPreferences `healthplan` | `profile` (JSON: sex, age, h, w, act, goal, tw, rate, waist, hip, neck, bf, wake, sleep, meals, veg, vegan, lf, gf, nofish, nonuts, noeggs, filled) |
| Свои времена приёмов пищи | `healthplan` | `mealOverrides` (JSON {индекс: минуты}) |
| События и напоминания (будильники) | `healthplan` | `events` (JSON-массив: id, type, title, times, days, en, ring, note, meal), счётчик `nextEventId` |
| Дневник питания | `healthplan` | `diary` (JSON-массив: id, d, m, fid, n, g, k, p, f, c, fb) |
| «Мои блюда», рецепты, свои продукты (в т.ч. с этикетки) | `healthplan` | `customFoods` (JSON-массив: id `c:<uuid>`, name, cat, k, p, f, c, fb, tags, src, portion, cooked, recipe[]) |
| Вес | `healthplan` | `weights` (JSON-массив {d, kg}) |
| Вода, отметки «сделано» | `healthplan` | `water_<дата>`, `done_<дата>` |
| Избранное, недавние | `healthplan` | `fav`, `recent` |
| Прочее | `healthplan` | `schema`, `menuSeed`, `permShown`, `lastVersionCode` (с 1.0.1) |
| Варианты меню | SharedPreferences `menu` | `m<индекс>` |
| Служебное (не пользовательские данные) | SharedPreferences `alarms` (`codes` — коды PendingIntent), `files/tessdata` (модель OCR из APK), `cache/photos` |
| Страховочные копии (с 1.0.1) | `files/backups/*.json` | формат экспорта |

Room/SQLite не используется — `fallbackToDestructiveMigration` и миграции БД не нужны. Если БД появится: только явные добавляющие `Migration`, `exportSchema = true` и тесты миграций; `fallbackToDestructiveMigration` запрещён.

### Правила для каждого обновления
1. **Не переименовывать и не удалять** файлы SharedPreferences, ключи, поля JSON, пути и форматы id. `versionCode` только растёт, подпись — тот же ключ (`~/.android/debug.keystore`), иначе обновление поверх невозможно.
2. **Новые поля — только необязательные со значением по умолчанию**; чтение старого JSON без них обязано работать (`StoreJsonTest`, `UpgradeCompatTest`). Неизвестные значения перечислений читаются как значение по умолчанию.
3. **Миграции** (`Store.migrate`) — под флагом версии схемы (`schema`), идемпотентные и только добавляющие: ничего не удаляют и не перезаписывают пользовательские значения.
4. **Начальные данные** (набор событий по умолчанию) создаются, только если соответствующих данных ещё нет (`events` отсутствует). Удалённые пользователем события не возвращаются.
5. **Снимок перед обновлением:** при первом запуске новой версии, если есть данные, автоматически пишется `files/backups/auto-before-update-[v<старая>-]to-v<новая>-<время>.json` (один раз на версию; хранится 10 последних).
6. **Резервное копирование Android** включено (`allowBackup=true`, `backup_rules.xml` для Android 8–11, `data_extraction_rules.xml` для 12+): включены `healthplan.xml`, `menu.xml`, `files/backups/`; модель OCR и `alarms.xml` исключены. В облако на Android 12+ — только при сквозном шифровании копии.
7. Перед выпуском: unit-тесты + проверка установки поверх предыдущего APK (`adb install -r`) с реальными данными.

### Экспорт и импорт
«Ещё → 💾 Данные: экспорт и импорт» (Storage Access Framework, без разрешений на память).
- **Экспорт данных** — один файл `healthplan-backup-ГГГГ-ММ-ДД-ЧЧмм.json`: `format` = `healthplan-backup`, `formatVersion` = 1, `appVersion`, `appVersionCode`, `schema`, `exportedAt`, `counts`, `data` { profile, mealOverrides, menuSeed, events, nextEventId, weights, diary, customFoods, favourites, recents, done, water, permShown, menuVariants }. Объекты сериализуются теми же функциями, что и хранилище.
- **Импорт данных** — проверка файла, сводка содержимого, затем:
  - «Добавить к текущим» — текущие данные не меняются, добавляется только отсутствующее (дубликаты по id / дате пропускаются; профиль берётся из файла, только если текущий не заполнен); повторный импорт ничего не дублирует;
  - «Заменить всё» — сначала автоматически сохраняется страховочная копия `files/backups/before-import-….json` (о чём сообщается), затем разделы из файла заменяют текущие; разделов, которых в файле нет, замена не касается.
  - После импорта — синхронизация приёмов пищи и перепланирование будильников.
- Совместимость: отсутствующие поля → значения по умолчанию, неизвестные поля/разделы игнорируются, файл более нового формата читается с предупреждением, повреждённые записи пропускаются и подсчитываются.
- Страховочные копии видны на том же экране: «Восстановить…» (через ту же сводку) и «В файл».
